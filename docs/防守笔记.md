## 已能讲清单

### 0. 项目一句话（对外口径）

工程标准符合性审查多智能体：五 agent 流水线（路由→检索→审查→校验→报告），
每个结论强制挂「条文原文+条款号+置信度」证据链，证据不足分级拒答不硬答；
pgvector+BM25 混合检索加重排，LangGraph 编排可断点续跑，七套评测数字支撑。

### 1. 环境（2026-09-16）

- **一句话价值**：一套 PostgreSQL 同时解决向量、全文检索、业务表，少一个组件。
- **数据流**：FastAPI → psycopg3 → Docker 里的 pgvector/pgvector:pg16 → HNSW 索引。
- **为什么 pgvector 不用 Chroma/FAISS**：Chroma/FAISS 停留在"demo 级"——没处理过
  分片、ANN 调优（m/ef_construction/ef_search）、持久化运维；pgvector 与业务表同库，
  条款号 join、全文检索、事务都是 SQL，M3 的 checkpointer 也复用 PG。
- **为什么条款号是天然主键**：入库时是结构化分块的切分单位与去重键；
  出报告时是证据三元组的溯源锚点、校验 Agent 程序化核对的对象。

### 2. 语料设计（2026-09-16）

- **一句话价值**：自写模拟标准 + 公开元数据，版权安全且结构可控，是分块/检索/评测的共同输入。
- **数据流**：corpus/*.md（章→节→条结构，含表格/图占位/跨标准引用/长度悬殊四个刻意难点）
  → 未来 rag.parse → chunks 表。
- **为什么埋难点**：真实标准本来就有表格和跨引用，语料必须逼真；且难点先入语料
  = 提前定好对照实验，评测一跑完 BadCase 能归因（"表格被切碎→改分块→数字提升"）。
- **为什么三份选机械/焊接/电气**：按测试目的选——机械与电气差异大测路由分流，
  焊接与机械有交集测多意图与检索边界。不是顺手写。

### 3. RAG 基础与证据门控（2026-09-16，三轮复述过关）

- **一句话价值**：RAG = 先查后答、照原文答，结论才挂得上"依据 X 条"；
  证据门控让这个"依据"不可能造假。
- **数据流**：文件 → 解析成目录树（章→节→条）→ 叶子条款 = 卡片(chunk)，
  引用句记进 refs（口诀：谁引用记谁）→ 向量化入库 → 检索 → 审查 → 三查 → 报告。
- **为什么按条款切**：chunk↔条款 1:1，"依据"才指得准、子串校验才成立；
  超长条款拆分后条款号=组地址、sub_idx=页码，核对时查整组。
- **三样检查（面试原题级）**：①条款号真实存在（代码查库）→ ②引用文本确为
  原文子串（代码比对）→ ③证据支持结论（独立 LLM 判定）。
  分工原则：前两样是事实核对零幻觉，第三样是推理核对只能靠模型——
  先代码后模型，能用代码的绝不交给模型。
- **为什么记忆深刻**：三轮复述，第 3 查（证据支持结论）连丢两次，
  最终靠"术语定义撑不起不符合"的反例应用题过关。

### 4. 向量检索原理（2026-09-16，复述过关）

- **一句话价值**：把"按意思找"变成"按距离找"，解决关键词匹配对不上口语表达的问题。
- **数据流**：卡片文字 → BGE-M3 → 1024 维坐标点；问题也变点 → 找最近 k 张
  （pgvector `<=>` 距离排序，HNSW 索引=小世界社交网络跳跃加速）。
- **核心性质（必背原句）**："意思相近的文字，坐标点挨得近"——
  同义不同字的 query 能命中全靠这一条（首答只说"按语义搜"是循环论证，
  被纠正后补上性质本身）。
- **两个为什么**：为什么 pgvector——向量+全文+业务表一个 PostgreSQL 全包；
  为什么 recall@5 用 5 不用 1——正确条文进前 5 候选圈即可，后面有 rerank 补救排名。
- **边界（引出下周课）**：向量不擅长精确匹配（条款号、标准号）→ 双通路混合检索。

### 5. BM25 与 RRF（2026-09-16，各一题过关）

- **BM25**：带智商的数词频 = 出现次数 × 词的稀有度 × 长卡修正。
  罕见词命中是黄金线索（"4.3.1" 只在 2/60 张卡 → 高分；"什么" 60/60 → 低分）。
  分工：**向量管意思，BM25 管字面**——编号/代号没有"意思"但有独特字面，
  恰好补向量的洞。PG 自带全文检索（chunks.tsv 字段），不用另养 ES。
- **RRF**：分数单位不同不能相加（体温 36.5 度 + 3 个苹果）→ 扔掉分数只看名次，
  贡献 = 1/(60+名次)，两路加总重排。口味：**两路都靠前的排前面**（评委共识
  压倒单路狂热）。

### 6. rerank 与多级拒答（2026-09-16，各一题过关）

- **rerank（cross-encoder）**：向量模型是双塔——问题和卡片各自算向量再比距离，
  **从没见过面**，快而糙；rerank 把问题和卡片**拼在一起当面核**，慢而精。
  所以是漏斗：全库 →[向量∥BM25→RRF]→ 前 20~50 →[rerank]→ 前 5。
  为什么不全库 rerank：慢+贵，海选可以批量预计算，面试必须一对一来。
- **多级拒答**：A 病在**库**（没得查，检索分数全线低）/ B 病在**依据**
  （查到了但撑不住）/ C 病在**输入**（扫描件解析不清）。
  C 的判定只看一件事：被审文件本身解析得清不清楚。
  接口：**三查任何一查不过 → 强制降级为 B 级拒答，绝不放行**。
  金句：拒答是设计出来的行为，不是能力不够的托词（评测三专门盯：该拒拒了吗、
  等级对吗、误拒了吗）。

### 7. 五 Agent 与 LangGraph（2026-09-16，4a~4d 全过）

- **4a 为什么拆五个**：①上下文专一（每岗位一页说明书）②轨迹分段落库可归因
  （坏结论能定位坏在哪一环）③**考生监考必须分离**——模型偏袒自己写的结论，
  自己查自己=门控作废 ④可单独换模型、可降级。
- **4b LangGraph**：State=病历本（整单任务的共享进展）/ Node=科室（一个 agent=
  一个函数，State 进出）/ 条件边=分诊规则（岔路回头路全显式）。
  checkpointer：**每走完一个 node 自动把 State 存档进 PG**，重启读最后一份存档
  从没跑的 node 继续。名词：supervisor 模式。对比：Chain 是焊死的直线。
- **4c 路由三层级联**：关键词（免费）→ 向量（便宜）→ LLM+查询改写（贵，兜底）。
  便宜层自信就停，贵的层不出场。**多意图两个嫌疑信号**：不同领域独占词同现 /
  向量 top2 分数接近且都高。置信度=领域独占性打分（一层）/ 与领域代表点的
  余弦相似度（二层）；阈值靠评测标定，不是数学推导。金句：词对了≠意图全了。
- **4d 审查 Plan-and-Execute**：先出结构化核对计划（去重/排序，不动手），
  再逐项执行写回 State（断点续跑的抓手）。对比 ReAct：自由但失控。
  **检查项**=从待审文档解析出的"待核对清单"的一行；报告=每项一行结论挂证据。
- **降级**：五合三（路由 / 检索+审查 / 校验+报告），底线：**审查与校验
  绝不合并**（运动员兼裁判）。

### 8. 可靠性、记忆、评测、MCP（2026-09-16~17，5a~5d 各过题）

- **幂等**：同一操作跑 N 次结果一样；靠 review_steps 表唯一键 (review_id, step_seq)，
  金句"幂等不写在 if 里，写在唯一键里"（防重复提交/断点重跑产生重复结论）。
- **熔断**：滑动窗口连续 N 次失败→跳闸→快速失败+该检查项标"服务降级"跳过+
  主流程继续+定时探测恢复（类比电闸）。核心：不陪废掉的服务耗时间。
- **记忆两件套**：工作记忆=滚动窗口+Compact 摘要（细节扔、结论留，防 token 爆炸
  和 lost in the middle）；长期记忆=经验库错题本（文档特征→常见不符合项，新单
  先查，降漏报）。**前者管单内记得住，后者管跨单用得上。**
- **七套评测**：一二三=三个关口（检索：三档对比+recall@5/MRR；审查：埋错法
  漏报/误报，漏报更致命；拒答：应拒正确率/不应拒误拒率）；四五六=记忆消融/
  压缩对比/断点恢复 n=10；七=回归（改动前后重跑固定子集）。
  纪律：评测集先于调参存在、负结果照记。
- **MCP**：工具调用的 USB-C 标准；standard_search/document_parse/citation_lookup
  三工具接 Claude Code；系统从"一个应用"变"一个能力平台"。

### 10. parsing 模块（2026-09-17，AI 代写+走读确认，3 段过，真实语料验证通过）

- **一句话价值**：md → 标准文档树，是结构化分块的直接输入；条款号=门牌号。
- **数据流**：三条正则（`## N`章 / `### N.N`节 / `**N.N.N**`条款）逐行扫描，
  doc/chapter/section 三只手边读边搭树；普通行拼给当前条款当续行（长条款跨行拼接）。
- **两个为什么**：①换章必须 `section=None`——否则下一章开头条款挂到上一章末节
  （位置地址会因约定漂移、条款号永不漂移，所以查找永远按 clause_no 不按位置）；
  ②`field(default_factory=list)` 防可变默认值被所有实例共享的经典坑。
- **测试设计**：三测试钉死边界（树形状/归位+拼接/换章重置回归）；区分两种红灯
  ——AssertionError=值不对，IndexError=结构空了（挂错地方）。
- **边界**：v1 不解析附录/表格/图占位/术语条（**3.1 术语名**格式特殊，v2）；
  章下直接条款用透传节接住（模型妥协，chunk 层路径去重）。
- **走读记录**：用户答对树地址 chapters[3].sections[1].clauses[0]，并理解其
  依赖"前言不入树"约定；测试红灯位置一答只对一半（漏了 IndexError vs
  AssertionError 之别，已补）。

### 11. chunking 模块（2026-09-17，3 段过，真实语料 20 条款→20 卡、id 全唯一）

- **一句话价值**：树 → 卡片，向量检索与"子串校验"的作业单元；chunk 与条款约 1:1。
- **数据流**：双层循环沿树走（章→节→条款）→ 每叶子条款一张卡 → 超 800 字按
  句子边界拆段，sub_idx 区分；路径按节算、透传节去重。
- **两个为什么**：①切分必须用零宽断言 `(?<=[。；])`——普通切分吞标点后卡片
  非原文精确子串，门控第 2 查会误杀正常结论强制降 B；②守恒断言
  `"".join(卡文) == 原文` 是"拆而不丢"的可执行版，不管实现怎么改、拼不回
  原文就红。
- **chunk_id 三段式**：组地址+页码，将来 chunks 表唯一键（幂等数据层落点）。
- **走读记录**：树地址/零宽断言（两轮，第一轮"结尾就是字符"含糊被打回）/
  守恒断言，全过。

### 12. store 模块（2026-09-17，3 段过，46 卡入库+幂等实证）

- **一句话价值**：卡片落库——向量、分词、正文一次写齐，重跑一万遍一份不多。
- **数据流**：md → parse → chunk → BGE-M3 批量向量（归一化+float32）→
  jieba 词串 → executemany 填坑 → ON CONFLICT DO NOTHING。
- **三个为什么**：①批处理=把每次计算调用的固定开销摊到所有条目；
  ②归一化让内积=余弦——是保险不是修正（防流水线某处用内积被长向量带偏）；
  ③业务主键+ON CONFLICT=幂等（实证：重跑处理 46、新增 0、总行数仍 46）。
  外键要求先插 standards 再插 chunks，顺序反了全拒。
- **运维坑（必记）**：本地模型加载必须 `HF_HUB_OFFLINE=1`，否则 transformers
  联网检查更新、被墙环境挂死 18 分钟。同理首次下载用 `HF_ENDPOINT=hf-mirror`。
- **现场验证**：口语查询"配合面粗糙度最多允许多少"→ top1=4.3.1（正确条文）、
  top2=4.3.2——查询词与卡片无一字相同，语义检索兑现。
