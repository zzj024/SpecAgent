# corpus/ 语料说明

## 语料边界（面试被问版权就这么答）

- **检索语料主体**：`SPGT*.md` 均为 SpecAgent 项目**自写模拟标准**，编号使用虚构前缀
  SPG/T，内容不复制任何真实标准条文，无版权问题。
- **公开元数据**：`metadata/`（待建）收录真实国家标准的**目录信息**（标准号、名称、
  发布年份），属公开事实信息；只做"标准库有哪些真实标准"的背景目录，
  不收录其条文原文。
- 待审文档（评测二的 30 份埋错文档）同样全部自写。

## 文件清单与命名

命名规则：`{标准号去掉分隔符}_{名称}.md`，如 `SPGT21001-2025_机械制图与尺寸公差.md`。

| 文件 | 领域 | 状态 |
|------|------|------|
| SPGT21001-2025_机械制图与尺寸公差.md | 机械（图幅/公差/粗糙度/形位公差） | 待把关 |
| SPGT21002-2025_焊接质量验收规范.md | 焊接 | 未写 |
| SPGT21003-2025_电气设备标识与安全要求.md | 电气 | 未写 |

三份虚构标准互相引用（21001 的 4.5 条引用 21002/21003），
用于构造跨标准引用与检索边界案例。

## 刻意埋入的分块难点（与 evals/retrieval 的 BadCase 归因对照）

以 21001 为例，这四处是**特性不是缺陷**，改进分块前后各跑一次评测一即可归因：

1. **表格**：表 A.1、表 A.2 在附录，但被正文条款（4.1.1、4.2.1）引用——
   固定长度切分会把表头与数据行分离，或把表格与引用它的条款切远。
2. **图表占位**：图 1、图 B.1 用文字语义描述占位（模拟将来 Qwen-VL 的产出），
   验证"图表描述与文本一起入索引"的检索收益。
3. **跨条款/跨标准引用**：4.5.1 引用 "SPG/T 21002—2025 中 5.2"、4.2.1 引用
   "附录 A 中表 A.2"——引用溯源与 B 级拒答的素材，解析时应抽取进 chunk 的 refs 字段。
4. **条款长度悬殊**：4.2.2 约 300 字 vs 4.1.2 一句话——固定长度切分在此必然
   把短条款合并或把长条款腰斩，是结构化分块的直接需求来源。

## 数值条款一览（将来评测二埋错的对照表）

这些条款含可核对的具体数值，是"人工埋错"的天然靶子（埋错=文档里写一个
违反这些数值的设计值）：

- 4.3.1：配合面 Ra ≤ 1.6 μm / 结合面 ≤ 6.3 μm / 非加工面 ≤ 25 μm
- 4.3.2：公差等级高于 IT7 → 配合面 Ra ≤ 0.8 μm
- 4.4.2：未注平面度 H/K/L = 0.3/0.5/1.0 mm
- 4.1.2 / 表 A.1：幅面尺寸与推荐比例系列
- 表 A.2：未注公差 m 级（默认）各尺寸段数值
- 6.2：抽检数量（≤50 抽 3 件，>50 抽 5% 且 ≥5 件）

## 评测一的选题方式

从三份语料抽 50 个条款，每条人工写 1 个"工程师会怎么问"的 query
（含同义改写变体），正确条款号作为 ground truth。**先建集、后调参**
（见 03-评测方案 评测纪律）。
